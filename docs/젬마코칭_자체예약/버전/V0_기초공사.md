# V0 기초 공사 — 원장님만 쓰는 예약 표

> 언제: 11월 1~2주 · 누가 쓰나: 원장님만 · 손님에게는 아직 아무것도 안 보임

## 끝나면 보이는 장면

원장님이 카드 타임테이블에 예약을 올리면 새 예약 표(`card_bookings`)에 들어갑니다. 이미 찬 시간에 일부러 겹치게 올려 보면 "이 시간은 이미 찼어요"가 뜨고 저장되지 않습니다. 휴무일과 개인 일정도 같은 표에 막아 둘 수 있습니다.

## 먼저 정할 것

[결정목록](../결정목록.md)의 D0-1 ~ D0-6. 하나라도 `미정`이면 그 항목부터 묻습니다.

## 만드는 순서

클로드에게는 한 번에 한 칸씩 시킵니다. 칸마다 시험이 통과하면 커밋합니다.

1. **영업시간·휴무 설정** — `store.js`에 설정 읽기·고치기 함수와 시험. settings JSON이라 SQL은 필요 없음. 카드 설정 화면에 고치는 칸.
2. **예약 표 만들기** — `supabase/schema.sql`에 `card_bookings`와 겹침 거절 규칙([설계안 4장](../설계안.md)). 원장님이 Supabase SQL 편집기에서 Run. Run 전에는 화면이 "표 없음" 안내를 보이게(지금 다른 표들과 같은 방식).
3. **들어갈 시간 계산** — `store.js`에 `availableSlots`와 시험(아래 목록). 화면에는 아직 안 씀.
4. **예약 넣는 서버 함수** — `api/book.js`. 원장 로그인 토큰을 확인하고(지금 `api/sms.js`와 같은 방식) 예약 넣기·막아 두기·취소. 겹쳐서 데이터베이스가 거절하면 "이 시간은 이미 찼어요"로 돌려줌.
5. **타임테이블 연결** — 올리기·막아 두기가 `api/book.js`를 거치게. 막대는 새 표에서 그림. 기록 남김 표시·가족 같이 올리기는 D0-5에서 정한 대로.
6. **전날 알림톡 확인** — `api/remind.js`가 내일 예약을 새 표에서도 읽는지 확인하고, [예약관리] 미리 보기에 내일 손님이 다 나오는지 봄.
7. **규칙 적어 두기** — 프로젝트 `CLAUDE.md`에 두 줄: "예약 넣기는 `api/book.js` 한 곳에서만", "`card_bookings`의 exclude 규칙을 지우지 않는다".

## `availableSlots` 시험 목록

- 예약 없는 날: 여는 시각부터 30분 간격으로, 시술이 마감 전에 끝나는 시각까지 전부
- 10:00 매직세팅(240분) + 정리 10분이 있으면 다음 커트(60분)는 14:30부터
- 30분만 빈 틈에는 60분 커트가 안 나옴
- 막아 둔 시간과 겹치는 시각은 안 나옴
- 잡아 둠(held)은 막고, 취소(canceled)는 안 막음
- 휴무일은 빈 목록
- 마지막 손님 뒤에는 정리 시간을 붙이지 않음(마감 시각까지만 끝나면 됨) — 을한 님께 맞는지 확인
- 지금 시각(`now`)을 인자로 받아, 지난 시각은 안 나옴

## 이 버전에서 살필 위험

- **알림톡이 빠질 수 있음.** 예약 원본을 바꾸는 순간 알림톡이 옛 명단만 읽으면 내일 손님에게 알림이 안 갑니다. 6번을 건너뛰지 않습니다.
- **명단에 붙은 기능이 깨질 수 있음.** 기록 남김 초록/빨강, 가족 같이 올리기, 대신 온 가족으로 바꾸기. 기존 시험(`timeline.test.js` 등)이 다 통과하는지 봅니다.
- **시간대.** `tstzrange`는 시간대를 품습니다. 서버는 세계 표준시로 돌기 때문에 한국 시간(+09:00)을 꼭 붙여 넣고 읽습니다. 안 그러면 9시간 밀린 예약이 생깁니다.
- **schema.sql Run을 잊음.** Run 전에는 저장이 안 되므로 화면에 안내가 떠야 합니다.
- **서비스 키.** `api/book.js`는 서버에서만 서비스 키를 씁니다. `config.js`나 화면 코드에 넣지 않습니다.
