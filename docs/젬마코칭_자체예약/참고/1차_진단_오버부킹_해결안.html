해결안

V1

지금 ~ 2주 · 네이버·핸드SOS는 그대로

원장님이 취소를 적는 손만 뺍니다

무엇을
  1. 취소를 저절로 알아채기. 취소 알림을 카드가 대신 받아 취소 기록(card_cancels)을 자동으로 적으면, 이미 만든 대기 문자가 원장님 손 없이 나갑니다. 알림이 메일로 오면 메일을 읽는 서버 함수, 문자나 푸시로 오면 아이폰 단축어 자동화가 다리가 됩니다.
  2. 빈 시간을 실제로 계산하기. 지금은 취소된 시술의 분만 봅니다. 앞뒤가 비어 있으면 실제 빈 시간은 더 길어서, 타임테이블로 계산하면 문자 받을 수 있는 손님이 늘어납니다.
  3. 문자 속 네이버 링크를 그 날짜 화면으로 바로 보냅니다.
왜

카톡에서 꼽은 아픔 중 "취소를 제가 알아야 시작돼요"는 원본을 옮기지 않아도 풀립니다. 네이버·핸드SOS를 건드리지 않으니 매장 위험이 없고, 대기 문자가 몇 번 나가고 몇 번 채워지는지 데이터가 쌓여 V2를 할지 정할 근거가 됩니다.

리스크
  • 취소 알림이 앱 푸시로만 오면 자동으로 읽기 어렵습니다. 첫 주에 실제 알림 한 건을 캡처해 확인합니다.
  • V1에서도 자리 잡아 두기는 여전히 안 됩니다. 선착순 그대로라는 점을 미리 분명히 합니다.
  • 자동으로 읽는 다리가 고장 나도 조용할 수 있습니다. 처음 화면 "오늘 확인할 것"에 "오늘 들어온 취소 N건"을 둡니다.
V2

11월 · V1 데이터를 보고 결정

요일 하나를 네이버에서 닫고 카드 전용으로 씁니다

무엇을

그 요일에는 단골 선예약 손님(10-28에 만든 선예약 연락)과 대기 손님이 카드 예약 페이지로 예약합니다. 카드가 원본이라 자리를 잡아 둘 수 있습니다.

취소 발생→빈 시간 계산→대기 1번에게 잡아 둠→문자 예 / 아니요→예: 확정, 알림톡 대상·아니요·시간 지남: 다음 손님
왜 요일

같은 날에 네이버 칸과 카드 칸이 섞이면 긴 펌이 경계를 넘어 다시 겹칩니다. 요일로 나누면 두 달력이 서로를 몰라도 절대 겹치지 않아서 동기화가 필요 없습니다. 잘 안 되면 그 요일을 다시 네이버에 열면 원래대로 돌아갑니다.

리스크
  • 네이버 노출·예약자 리뷰가 줄 수 있습니다. 원래 네이버 신규 예약이 적은 요일을 고릅니다.
  • 단골이 네이버 예약에 익숙합니다. 첫 달은 선예약 문자에 링크를 넣는 정도로 작게 시작합니다.
  • 예약 페이지가 고장 나면 그날 예약이 안 들어옵니다. 운영 책임이 으라 님에게 옵니다.
  • 30분씩 3명이면 자리가 1시간 반 묶입니다. 카드에 쌓인 "며칠 전 취소" 기록으로 잡아 두는 시간을 정합니다. 예: 3일 이상 전 취소는 2시간, 당일은 15분.
  • 정액권 원본은 여전히 핸드SOS입니다. 핸드SOS 해지는 따로 정할 일입니다.

넘어갈 때

V2를 한 달 돌려 오버부킹 0건, 원장님이 끼는 일 0건, 단골이 링크 예약을 불편해하지 않을 때. 이때 핸드SOS의 역할과 비용을 다시 따집니다.

V2 구현 핵심

겹침은 화면이 아니라 데이터베이스가 막습니다

1인 샵은 의자가 하나라서 규칙은 하나면 됩니다. 같은 시간에 예약 두 개가 겹치면 안 된다. 이 규칙을 Supabase 표에 걸어 두면 두 사람이 동시에 눌러도 한 명만 들어갑니다.

create extension if not exists btree_gist;

create table card_bookings (
  id          bigint generated always as identity primary key,
  customer_id bigint,
  service     text not null,
  slot        tstzrange not null,           -- 시작~끝, 시술 시간표의 분으로 계산
  status      text not null default 'held', -- held 잡아 둠 / confirmed 확정 / canceled
  hold_until  timestamptz,                  -- 잡아 둔 자리가 풀리는 시각
  created_at  timestamptz not null default now(),
  -- 잡아 둔 것·확정된 것끼리는 1분이라도 겹치면 저장이 거절된다
  exclude using gist (slot with &&) where (status in ('held', 'confirmed'))
);
클로드 코드에 이렇게 넘깁니다card_bookings 표를 만들고, 예약 넣기는 서버 함수 하나(api/book.js)에서만 한다. 넣기 전에 hold_until이 지난 held를 canceled로 바꾸고, 겹쳐서 DB가 거절하면 "방금 다른 분이 잡았어요"로 보여 준다. 손님 확인은 wait.html의 확인번호·하루 5번 제한·봇 거르기를 그대로 쓴다.

확인된 것과 아닌 것

"못 찾음"은 검색으로 찾지 못했다는 뜻이고, 없다고 확정된 것은 아닙니다.

질문결과내용
핸드SOS가 시술 시간만큼 막아 주나확인됨네이버 예약이 들어오면 핸드SOS에 설정한 시술 시간만큼 자동 차단. 예약은 즉시 자동 확정만 지원. 출처
네이버 예약 공개 API못 찾음연동은 핸드SOS·공비서·뷰카 같은 제휴 프로그램만 확인됨
네이버 자체 대기·빈자리 알림못 찾음없다는 확증은 아님
취소 알림이 오는 경로일부 확인스마트플레이스센터 앱 푸시는 있음. 취소 메일·문자는 확인 못 함 출처
대기 자동 배정을 해 주는 프로그램국내 못 찾음공비서는 대기 등록 기능이 있어 보이나 자동 배정인지는 불명. 해외 Zenoti는 V2와 같은 흐름(1순위에게 알림, 정한 시간 안에 답 없으면 다음 사람)을 제공 출처
핸드SOS 요금일부 확인홈페이지에 월 19,900원 프로모션 문구. 연동 포함 여부는 고객센터 1544-9368

정리하면 시술 길이 오버부킹은 핸드SOS로 이미 풀려 있어서, 오버부킹 때문에 네이버를 떠날 이유는 약합니다. V1이 되느냐는 취소 소식을 메일·문자·핸드SOS 중 어디서 받을 수 있느냐 하나에 달려 있습니다.
